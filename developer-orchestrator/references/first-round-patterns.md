# 首轮编排模式

> 本文档定义首轮模式（从零开发）的编排要点：首轮卡片类型与 Phase 结构、首轮与增量的编排差异、首轮常见陷阱。

---

## 首轮卡片类型与 Phase 结构

首轮产出**全量**卡片（区别于增量的 4-8 张，按场景）。结构如下：

| Phase | 层 | 卡片 | 说明 |
|-------|----|------|------|
| 0 | 契约层 | P0-DB（串行，唯一阻塞项）→ P0-Independent + P0-Auth（并行）→ P0-Seed → 契约冻结卡 / 共享约定卡 / Hub File 集成补全卡 | 先行冻结；契约冻结卡产出 `contracts/` 六件套 |
| 1+ | 领域层 | 每个限界上下文一张**全栈卡**（后端 + 前端同卡） | 并行；blocked_by 走 BFS 依赖链（非 `[]`） |
| 最后 | 集成层 | 集成闭环卡 + 封版归档卡 | 串行收口；验证范围 = **全部领域** |
| 最后之后 | 刷新层 | 状态刷新卡 | 反写 `contracts/` 为 Round 2 准备 |

### 首轮特有卡片（增量不会生成）

| 卡片 | 职责 | 为什么首轮特有 |
|------|------|--------------|
| **契约冻结卡** | 产出 `contracts/` 六件套（openapi.yaml + schema.sql + events.yaml + naming.yaml + routes.yaml + cross-context-writes.md） | 这是增量的「唯一真相」源头——首轮必须创建，增量消费已有 |
| **Phase 0 全部基础设施卡** | DB DDL、认证/CSRF/Session 中间件、WebSocket 服务、路由骨架、seed、脚手架 | 增量跳过（已存在且可运行） |

### 首轮与增量共有的收口卡（语义不同）

集成闭环卡、封版归档卡、状态刷新卡在**两种模式都生成**，区别在：

| 收口卡 | 首轮 | 增量 |
|--------|------|------|
| 集成闭环卡 | 验证**全部领域** + 全部核心旅程 | 验证**新域 ↔ 已有域** |
| 封版归档卡 | 10 项检查 + 归档 + git tag（不含 README 更新） | 10 项检查 + **跨轮集成检查** + 归档 + git tag + **README 更新** |
| 状态刷新卡 | 从首轮代码反写 contracts/（首轮 → Round 2） | 从本轮增量代码反写 contracts/（Round N → N+1） |

---

## 首轮与增量的编排差异要点

| 维度 | 首轮 | 增量 |
|------|------|------|
| 编排的「真相」来源 | 源文件（无唯一真相） | `contracts/`（唯一真相） |
| 输入缺失的后果 | 不阻塞——子 skill 推断 | 阻塞——冲突检测/外键引用无法执行 |
| Step 1 前置 | 环境就绪（Docker / 半成品续接） | 状态刷新（8 项一致性检查） |
| 冲突检测 | 无（greenfield，无已有契约可冲突） | 路径/事件/命名/外键 vs 已有契约 |
| 领域卡 blocked_by | BFS 依赖链（Phase 0 先行冻结） | 全部 `[]`（基础设施已就绪） |
| 卡片规模 | 8-20 张（全量） | 4-8 张（仅新域） |

## 首轮常见陷阱

| 陷阱 | 后果 | 规避 |
|------|------|------|
| 漏掉契约冻结卡 | 首轮跑完后 `contracts/` 不存在 → Round 2 增量无法启动 | Step 4 验证清单必须含「契约冻结卡存在」 |
| 领域卡 blocked_by 写成 `[]` | 领域卡抢在 Phase 0 前执行 → 依赖未就绪，验证步骤误判「自己代码有 bug」 | 首轮领域卡 blocked_by 必须是 BFS 链，不能照搬增量的 `[]` |
| 漏掉状态刷新卡 | 首轮代码与 contracts/ 脱节 → Round 2 的「唯一真相」过期 | Step 4 验证清单必须含「状态刷新卡存在」 |
| 把首轮当增量做（跳过 Phase 0） | 系统无基础设施，领域卡 import `requireAuth` 等 → `Cannot find module` | 先判模式：无 `contracts/` + 无 `docs/trace/runs/` = 首轮 |
| 向用户索要不必要的源文件 | 首轮输入是「有多少用多少」，缺失类别可推断 | 参照 `input-file-rules.md` 首轮分级——缺类不阻塞，只说明推断方式 |

## 首轮提示词模板

用户只需提供源文件路径 + 项目名：

```
首轮开发：基于以下源文件生成 <项目名> 的完整架构设计与 Issue 卡片。
源文件：<路径列表，或"当前目录下的 ddd/、src/、api/ 等">
```

**不需要提供的内容**（skill 自动处理）：
- ❌ 不需要描述 Phase 划分（子 skill 分析 B 并行化推断）
- ❌ 不需要指定技术栈（architecture-design-generator PART 4 技术约束确定）
- ❌ 不需要逐文件说明内容（子 skill 自动分类）
- ❌ 不需要描述认证/角色方案（子 skill 分析 A + PART 6.2 默认方案）

**触发词**：`首轮开发`、`从零开发`、`新项目`、`生成完整架构设计`、`完整开发流程`。

> 裸 `开发` 一词不触发本 skill——它太宽泛，会抢占「仅架构设计 / 仅拆卡」单步场景，应引导用户用「首轮开发 / 增量开发」等明确词。
