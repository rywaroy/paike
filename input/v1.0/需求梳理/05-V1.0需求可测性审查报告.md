## 二、整体判断

清单的模块覆盖与验收骨架是完整的：M1-M5 + 基础支撑全量 19 条 REQ 均有「做什么 / 关键规则 / 交互与数据 / 验收口径 / 优先级 / 角色」六要素，三类核心冲突（REQ-CE-001）与非功能验收边界（D3：50 班≤5 秒、1000 条≤3 秒、日志永久留存）已作为系统级约束贯穿，D6-D10 拍板结论也已落回正文。整体可测性基础良好。

主要缺口集中在**系统级横切面**而非具体模块细节：① 整个清单未出现「用户登录 / 账号 / 角色分配」相关的 REQ，而 AT-001（教师仅可见本人课表）、AT-003（教师仅可查本人空闲时段）等明确的角色权限边界强依赖身份判定，权限类验收目前缺少可执行的落点；② 「排课方案（草稿）→ 发布为正式课表 → 学期存档」这一核心状态流转未在任何 REQ 中闭环，导致一键排课、拖拽调课、工作量统计、导出、日志的用例边界存在歧义；③ 排课引擎的正确性验收依赖「冲突数 = 0」的宏观断言，缺少小型确定性输入→期望输出的验收样例；④ 「关键操作」「被引用数据的删除保护」等通用规则缺少可判定清单。

上述四项均为「口径补齐后在用例设计前即可消化」的类型，不涉及 P0 级主流程阻塞；建议在进入高保真原型阶段前，将本报告 §五 的 6 项待确认事项并入待拍板清单一次确认。

## 三、建议调整清单

### 建议 001｜用户登录与账号 / 角色权限体系无 REQ 落点

- 优先级：P1
- 建议类型：权限前置
- 依据位置：04 清单 §1 全表（19 条 REQ 无身份权限类）；02-名词统一 §一 定义了「教务管理员 Admin / 普通教师 Teacher」两角色及权限边界（管理员可跨班级/跨教师操作，教师仅本人）
- 当前材料表现：清单中 AT-001、AT-003 等 REQ 明确写了角色限权（"教师仅可见本人课表/本人关联班级课表""教师仅可查询本人空闲时段"），但没有任何 REQ 定义登录认证、账号来源、角色分配、管理员初始化方式；也未说明教师端如何访问系统。
- 建议调整：建议确认 V1.0 是否包含「用户登录 / 账号 / 角色分配 / 默认管理员初始化」能力并补齐对应 REQ（可新增身份权限域或归入 LG/基础支撑）；若 V1.0 以单校内部部署、仅管理员本机使用为交付边界，也建议在清单中显式声明「账号体系与角色分配由 V1.1 提供」以避免权限验收悬空。
- 对测试工作的影响：AT-001 / AT-003 的角色权限用例、越权访问用例、权限变更用例均依赖登录态与角色判定，无此落点则权限类验收与用例无法形成可执行断言。
- 待确认对象：产品
- 确认状态：待确认

### 建议 002｜「发布 / 存档」生命周期与状态流转未闭环

- 优先级：P1
- 建议类型：状态流转
- 依据位置：REQ-AP-001（"排课方案，发布前可预览、微调、另存"）、REQ-CM-001（"发布"为关键操作需二次确认）、REQ-LG-001（"学期存档，存档后只读可导出"）、REQ-BD-001（学期列表含"状态"字段与"存档后只读"）
- 当前材料表现：清单中出现「方案（草稿）→ 发布 → 存档」多个状态词，但未定义：发布是否为全局唯一、发布后正式课表是否仍可被拖拽调课（AT-002 的作用对象）、发布与存档的关系（存档是否需要先发布）、未发布而直接切换学期时如何处置、存档的触发方式。
- 建议调整：建议在 REQ-AP-001 或基础支撑补充「排课方案(草稿) → 发布为正式课表 → 学期存档」的完整状态流转定义，含唯一性、可编辑性、覆盖规则、学期切换对未发布内容的约束。
- 对测试工作的影响：影响一键排课、调课、工作量统计（统计对象是方案还是正式课表）、导出（导出正式课表）、日志覆盖面等一批准入用例与回归边界。
- 待确认对象：产品
- 确认状态：待确认

### 建议 003｜「微调」与「拖拽调课」的关系 / 边界未明确

- 优先级：P1
- 建议类型：口径一致性
- 依据位置：REQ-AP-001（"方案可预览、微调、另存"）、REQ-AT-002（"拖拽可视化调课"，实时冲突校验、撤销/重做）
- 当前材料表现：两处都涉及"调整课程位置"，但一个出现在「排课方案」上下文、一个出现在「课表视图」上下文；是否同一套交互能力、是否都经过 CE-001 冲突校验与 CM-001 撤销/重做、在"微调"中是否也受锁定课程（REQ-AP-002）保护，均未说明。
- 建议调整：建议明确"微调"= 在未发布方案上复用 AT-002 拖拽调课能力（同一冲突校验与撤销/重做规则），并明确锁定课程在微调中不可被移动；若有意区分，请给出各自的校验与权限差异。
- 对测试工作的影响：避免两处实现重复且校验口径不一致导致的回归漏测；影响 AT-002 与 AP-001 的组合用例。
- 待确认对象：产品、研发
- 确认状态：待确认

### 建议 004｜排课无解 / 无法满足全部课时的异常处理未定义

- 优先级：P1
- 建议类型：异常处理
- 依据位置：REQ-AP-001（"三类核心冲突为 0，一键自动生成全校课表"）、REQ-AP-002（锁定课程）、REQ-BD-004（规则冲突"明确提示而非静默忽略"）
- 当前材料表现：清单只描述了"生成成功、冲突为 0"的成功路径；对硬约束无法同时满足（教师课时不足、场地不足、锁定课程挤占导致无法放满全部每周课时）时系统的行为缺失：是产出"冲突数>0 的方案"、报"无法完成排课"、还是部分成功 + 提供"未排课时清单"。
- 建议调整：建议补充「无解 / 部分满足」场景的输出与交互口径（如"未排课时清单"并可跳转到可调对象），并说明此时是否允许保存为方案。
- 对测试工作的影响：一键排课主流程的异常分支、CE-001 冲突明细展示、未排课时统计的用例均为空档。
- 待确认对象：产品
- 确认状态：待确认

### 建议 005｜排课引擎缺乏确定性验收样例

- 优先级：P1
- 建议类型：验收与观测
- 依据位置：REQ-AP-001 验收口径（"三类核心冲突为 0"+ 非功能"50 班≤5 秒"）、REQ-CE-001 验收口径（"全部场景三类核心冲突为 0"）、REQ-BD-004 验收口径（"按规则约束产出"）
- 当前材料表现：引擎正确性验收依赖"冲突为 0"的宏观断言与 50 班性能，缺少小规模确定性输入→期望输出的样例；"避免静默忽略以避免规则冲突"无具体可判定样例。
- 建议调整：建议补充 1-2 个排课引擎验收样例（例如最小规模：2 班 + 2 教师 + 2 门课 + 1 功能室，赋予连堂/禁排/免排约束 → 期望课表逐项满足约束且三类冲突为 0），作为 AP-001 / CE-001 / BD-004 的共同断言基准，供原型演示与回归复用。
- 对测试工作的影响：直接影响引擎用例的可判定性与回归自动化，缺样例则验收只能靠人工观察课表。
- 待确认对象：产品、研发
- 确认状态：待确认

### 建议 006｜「关键操作」判定清单未定义

- 优先级：P1
- 建议类型：口径一致性
- 依据位置：REQ-CM-001（"关键操作（删除、发布、覆盖方案等）二次确认"）、REQ-LG-001（"关键操作全量记录日志""关键操作 100% 留痕可追溯"）
- 当前材料表现：两处 REQ 都依赖"关键操作"这一概念（既影响二次确认，也影响日志覆盖率），但清单仅给出"删除、发布、覆盖方案"三个示例，未给出完整可判定的关键操作清单或判定规则。
- 建议调整：建议在 REQ-CM-001 / REQ-LG-001 落点补充关键操作枚举（如：删除类、发布类、覆盖方案、切换学期、批量导入提交、二次确认类操作等）或判定规则，保证二次确认与留痕覆盖范围可一一对账。
- 对测试工作的影响：二次确认范围与日志留痕覆盖率的验收用例需要逐项枚举；无判定清单则"100% 留痕"无法验收。
- 待确认对象：产品
- 确认状态：待确认

### 建议 007｜被引用数据的删除保护规则未定义

- 优先级：P1
- 建议类型：数据规则

- 建议调整：建议补充被引用数据的删除保护口径（引用级删除提示或禁止），并说明删除学年/学期/模板时对历史课表与存档的影响。
- 对测试工作的影响：BD-001~006 的删除类用例、引用完整性用例、数据恢复场景均受影响。
- 待确认对象：产品
- 确认状态：待确认

### 建议 014｜名词统一文档中「课时均衡 / 上下午均衡 / 固定时段强制空课」无 REQ 落点
