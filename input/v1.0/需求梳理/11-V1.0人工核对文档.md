> 用途：把「需要人工拍板 / 校验 / 确认」的内容，翻译成不用懂术语也能看懂的大白话，供本环节负责人逐条核对。**核对通过 = 本环节放行；未核对通过，不得进入下一步，也不得封版。**

## 怎么核对（三种方式任选）
- **全部采纳**：没问题，回复「无异议」即可（视为全部采纳）。
- **个别调整**：报「编号 + 你的新说法/新要求」，如「口径-7 改成：班级名允许管理员自定义前缀」。
- **个别否决**：报「编号 + 否决原因」，我们会停下来和你对齐再改。

## 一、需求总览核对（共 20 项，来自需求清单 04）

> 下面 20 项是 V1.0 要做的全部功能。逐条过一遍，**没意见的就是采纳**。

### A. 基础数据（先把学校的基本信息管起来）｜ 7 项

| 编号 | 系统要做的事（大白话） | 建议 |
|------|------------------------|------|
| REQ-1 | 学期管理：维护「学期」，可切换当前学期、单独存档；新建学期必须**绑定一个作息表**，否则不能一键排课；存档后的学期只读、可导出 | 采纳 |
| REQ-2 | 作息模板：维护「上课时间表」模板（每天第几节、几点到几点、周几上课），一套模板可给多个学期共用；改模板不影响已用旧模板排出课表的历史学期 | 采纳 |
| REQ-3 | 班级/年级：可自己新增/修改/删除年级和班级；班级名**自动按「年级（序号）班」生成**（如「高一（1）班」），序号 1–99，**不允许随意输入文字** | 采纳 |
| REQ-4 | 科目与课时：维护科目每周几节、是否连堂（如理化生 2 节连上）、哪些时段禁排（如体育美术不排第 1 节/最后一节）；科目名受控，**不允许「语」和「语文课」这种同义不同名并存** | 采纳 |
| REQ-5 | 教师信息：教师是独立档案（工号唯一、格式受控），可增删改查；可配置每个老师教哪个班哪些课、每周几节、哪天哪节不排；**新增老师可一键开通教师登录账号** | 采纳 |
| REQ-6 | 场地/功能室：普通教室和音乐室/美术室/实验室统一管理，用「类型」区分；功能室全校共享、按占用校验，普通教室归班级固定；**班级人数超过教室容量不能排进去**，要提示换场地 | 采纳 |
| REQ-7 | 合班课：多个班合在一起上课（如体育大课），共用一个老师、一间教室、同一节课；参与班级从列表里选 | 采纳 |

### B. 自动排课（核心功能）｜ 3 项

| 编号 | 系统要做的事（大白话） | 建议 |
|------|------------------------|------|
| REQ-8 | 一键智能排课：点一下，按基础数据和规则自动排出全校课表；**老师不冲突、班级同一节不出现两门课、教室不撞车，三类冲突全为 0**；可预览、可另存多套方案 | 采纳 |
| REQ-9 | 课程预排与锁定：排课前可手工定好某些课（固定时间/老师/教室），自动排课时**保持原样不动**；锁定的课不可被自动或拖拽调整，可解锁 | 采纳 |
| REQ-10 | 复杂场景排课：支持 单双周（单周、双周两套课表轮换）、走班（学生按科目去指定教室上）、跨年级授课（同一位老师教多个年级） | 采纳 |

### C. 课表查看与调课｜ 3 项

| 编号 | 系统要做的事（大白话） | 建议 |
|------|------------------------|------|
| REQ-11 | 多维课表：按 班级 / 老师 / 全校 / 场地 / 任课 五种角度查看课表；**老师只能看自己的课表和自己的班的课表，管理员能看全部** | 采纳 |
| REQ-12 | 拖拽调课：把课表里的课用鼠标拖到新的时间/教室完成调课；落下去之前先查会不会冲突，**冲突放不进去并提示**；支持撤销/重做 | 采纳 |
| REQ-13 | 空闲时段查询：查某个老师/某个班哪些节是空的，方便安排调课；**老师只能查自己**，管理员可查任何人 | 采纳 |

### D. 统计与打印｜ 3 项

| 编号 | 系统要做的事（大白话） | 建议 |
|------|------------------------|------|
| REQ-14 | 教师工作量统计：按周/学期统计每个老师上了多少节课，分 普通 / 连堂 / 合班 / 加班 四类，**不重复计算** | 采纳 |
| REQ-15 | Excel 全维度导出：基础数据、课表、统计都能导出 Excel，**导出来的字段和系统里显示的一模一样** | 采纳 |
| REQ-16 | 自定义模板打印：可自定义打印版式（纸张/校徽/标题），把课表打成可张贴的纸版；预览和打印结果一致 | 采纳 |

### E. 后台支撑（保障机制）｜ 4 项

| 编号 | 系统要做的事（大白话） | 建议 |
|------|------------------------|------|
| REQ-17 | 冲突校验引擎：全程实时检查「老师时间冲突 / 班级同节多课 / 场地占用」三类冲突，**有冲突就拦截、高亮，并把冲突明细展示出来、给出修改建议**；**若冲突由前面的排课限制（约束/配置）引发，可选「只本次忽略」——仅本次排课放行通过、不修改系统配置、后续排课仍按系统设置的规则执行（豁免不落库）——或「去修改配置」——跳转对应配置维护入口修改约束后重新排课**（D21 新口径） | 已修订采纳 |
| REQ-18 | 数据通用规则：所有数据统一支持增删改查、批量导入导出、撤销/重做；**删除、发布、覆盖方案、切换学期、批量导入、学期存档、保存调课这 7 类关键操作都要二次确认**；**被引用的数据（有任课记录的老师、被学期用着的作息表等）不允许直接删** | 采纳 |
| REQ-19 | 操作日志与多学期存档：谁、什么时候、做了什么，全程留痕可查；课表存档后**只读、可导出、不可改**；多个学期数据互不干扰 | 采纳 |
| REQ-20 | 用户与角色：系统有「教务管理员」和「老师」两种账号；老师登录后**看不到别人的课表和管理功能**，权限之外的操作被拒绝并提示 | 采纳 |

## 二、关键验收口径核对（数字红线，5 项）

> 这几条是「做到什么程度算达标」的硬性数字，做开发和验收都按它来。

| 编号 | 达标要求（大白话） | 建议 |
|------|--------------------|------|
| V-1 | **排课速度**：50 个班的学校，点一键排课后，5 秒内出结果 | 采纳 |
| V-2 | **导出速度**：一次导出 1000 条数据，3 秒内完成 | 采纳 |
| V-3 | **日志留存**：操作日志永久保存，不被清理 | 采纳 |
| V-4 | **导入上限**：一次批量导入最多 5000 行，**超过就拒绝并提示**，不能悄悄只导一部分 | 采纳 |
| V-5 | **冲突零容忍**：引擎排课结果三类核心冲突为 0（一个都不允许出现）；用户显式选择「只本次忽略」属**人工豁免路径**、不计为静默冲突，仅本次排课生效、不改系统配置、后续仍按系统设置执行 | 采纳（含豁免说明，D21） |

## 三、关键业务口径核对（已拍板的决策，请你复核 10 项）

> 下面这些是以前拍定的关键决策，直接影响系统怎么用、对不对你的意。逐条复核，如无异议即采纳。

| 编号 | 决策内容（大白话） | 对应决策 | 建议 |
|------|--------------------|---------|------|
| 口径-1 | 新建学期**必须绑定一个作息表**，没绑不能一键排课 | D8 | 采纳 |
| 口径-2 | 排课的流程是：先出「草稿方案」→ 预览/微调满意后「发布」为正式课表 → 「存档」后只读；**一个学期只能有一份正式课表**，要覆盖旧的要二次确认 | D12 | 采纳 |
| 口径-3 | 排课排不满时：系统会给出「未排出来的课清单」，可以点进去看是哪几节课、差在哪，方案能先保存、人再接着手工调 | D14 | 采纳 |
| 口径-4 | **最小验证样例（已采纳 2026-09-17 09:36:00，复核即可）**：拿 2 个班+2 位老师+2 门课+1 间功能室的小例子，带「连堂/禁排/免排」约束，排出符合逐格期望表、三类冲突为 0 的课表，才算引擎达标 | D15 | 已采纳 |
| 口径-5 | 7 类关键操作（删除/发布/覆盖方案/切换学期/批量导入/学期存档/保存调课）都弹确认框；**被引用的数据不能直接删**，要给提示 | D16 | 采纳 |
| 口径-6 | 班级人数超教室容量=硬性不允许，直接提示换场地；多人同时改同一批数据时，采用「提示刷新/行级锁」防乱 | D19 | 采纳 |
| 口径-7 | **命名受控**（上次你的反馈）：班级、科目、场地、合班的名字都不许随意输入，按规范格式录入；教师工号格式受控且唯一。请复核是否符合你的要求 | D20 | 采纳 |
| 口径-8 | 权限边界：老师只能看自己的课表、自己班的课表、查自己的空闲时段；**看不到全校教务管理和导出打印等管理功能** | D11 | 采纳 |
| 口径-9 | 单双周：第 1 周按「单周」起算，按周次奇偶轮换；遇到节假日停课，**周次不顺延** | D18 | 采纳 |
| 口径-10 | 加班统计：V1.0 先展示「加班」字段和基础口径，**加班具体怎么判定下一版本再细化** | D7 / Q3 | 采纳（V1.1 落地） |
