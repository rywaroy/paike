## 2. 各模块详细需求

### M1 基础数据管理（BD）

#### REQ-BD-001 学期管理 ｜ P0 ｜ Admin
- **做什么**：维护学期主数据，作为排课与数据归集的时间单元；支持多学期独立存档、一键切换当前学期。
- **关键规则**：每个学期**仅引用一个作息模板**（D4）；**学期新增强制绑定作息模板，未绑定不得进入一键排课**（D8**✅**）；切换学期后，该学期引用哪套作息模板随之生效；学期存档后只读可导出；学期状态枚举＝未开始 / 进行中 / 已结束 / 已存档，存档由管理员手动触发且先决为该学期已发布正式课表（D12）。
- **交互与数据**：学期列表（学期 / 学年 / 起止日期 / 引用作息模板 / 状态）；新增学期时下拉选择作息模板（必选）；支持批量导入。
- **验收口径**：可新增 / 编辑学期并绑定任一现有作息模板；未绑定作息模板的学期不可触发一键排课；切换学期不发生跨学期数据串扰；已存档学期不可编辑、可查看导出。已拍板：D8 强制必选。

#### REQ-BD-002 作息模板 ｜ P0 ｜ Admin
- **做什么**：维护作息模板独立主数据，可配置**多个版本**；定义工作日 / 周末 / 晚自习上课节次、每节起止时间、开放星期等规则。
- **关键规则**：**与学期解耦**（D4）——任一模板版本可被复用到任意学期；模板改版不影响已引用该模板的历史学期；新增版本基于历史版本复制。
- **交互与数据**：模板列表 + 版本记录（v1/v2/v3）；模板编辑表单（模板名称、基于版本、开放排课星期、节次时间表「第 1 节 08:00-08:45 …」）；保存即生成新版本。
- **验收口径**：可创建模板并配置节次 / 开放星期等规则；同一模板可被多个学期同时引用；修改模板不会回改历史学期已生成的课表数据（版本快照生效）。

#### REQ-BD-003 班级 / 年级管理 ｜ P0 ｜ Admin
- **做什么**：维护年级-班级-班主任-人数的组织数据；**年级为独立可管理实体**（可新增 / 编辑 / 删除，班级归属年级）；系统自行维护，不做外部对接（D5）。
- **关键规则**：班级归属于某个年级（归属年级从年级列表下拉选择）；**班级名称格式受控（D20）**：自动按「年级（序号）班」生成（如「高一（1）班」），序号为 1-99 整数受控录入，**禁止自由文本直接输入班级名**；班级人数作为排课与场地容量校验输入；支持批量导入导出（导入模板按同一命名规范校验，违反规范行级报错）。
- **交互与数据**：年级区（受控名称列表：高一/高二/高三 或 七年级…九年级，支持新增 / 编辑 / 删除，新增后纳入受控列表）+ 班级列表（班级名称 / 所属年级 / 班主任 / 人数）表格增 / 删 / 改 / 查；新增班级＝选择所属年级 + 输入受控序号，系统自动生成规范班级名称。
- **验收口径**：可独立增删改查年级；新增/编辑班级时输入不符合「年级（序号）班」格式或序号超出 1-99 范围被拒绝并提示；删除被班级引用的年级受引用保护提示（D16）；批量导入时按模板校验字段与命名规范，异常行给出行号级提示。

#### REQ-BD-004 科目与课时规则 ｜ P0 ｜ Admin
- **做什么**：维护科目及每周课时规则：每周课时数、时段优先、连堂偏好、禁排规则；**科目为独立主数据，名称受控录入（D20）**。
- **关键规则**：科目课时规则是排课引擎约束输入；连堂偏好（如理化生强制 2 连课）、禁排规则（如体育 / 艺术不排第 1 节 / 最后一节）作为软约束 / 硬约束配置；课时均衡 / 上下午均衡 / 固定时段强制空课或指定课程三类约束纳入 V1.0 作为**可配约束项**（默认关闭，启用即作为软约束参与排课，D17）。（D17**✅**）；**科目名称从受控规范列表选择，新建科目经受约束录入纳入列表后复用，禁止同义不同名并存**（如「语 / 语文课」）。
- **交互与数据**：科目列表 + 课时规则编辑（每周课时、连堂偏好、禁排时段、时段优先）；新增 / 编辑科目名称、课时规则。
- **验收口径**：可配置科目每周课时与约束；可新增 / 编辑科目，名称违反受控规范时录入被拒绝；排课引擎按规则约束产出，规则冲突时给出明确提示而非静默忽略。

#### REQ-BD-005 教师信息与任课约束 ｜ P0 ｜ Admin
- **做什么**：**教师为独立主数据实体，支持完整增删改查（D20）**；维护教师-科目-班级-场地对应关系及配套约束：免排时段、禁排、课时数、连堂偏好等（任课约束 = 基础数据，非排课结果）。
- **关键规则**：教师主数据字段＝工号 / 姓名 / 性别 / 手机号 / 进退校状态，**工号唯一且格式受控（如 `T` + 数字编号，D20）**；任课约束跨科目 / 班级 / 场地多维绑定；免排（主动配置）与禁排（业务规则限定）语义区分（见名词统一）；课时均衡类约束作为可配软约束联动 REQ-BD-004（D17）；**教师主数据联动 REQ-AU-001 用户角色**：新增教师可一键开通 Teacher 登录账号（D11 / D20）；删除有任课 / 关联记录的教师受 D16 引用保护并提示引用关系。
- **交互与数据**：教师列表（工号 / 姓名 / 性别 / 手机 / 状态）+「＋ 新增教师」「编辑」「停用 / 删除」入口 + 教师查询；新增 / 编辑教师表单（工号受控、姓名、性别、手机、进退校状态、一键开通登录账号开关）；任课配置表单（教师 → 科目 + 班级 + 场地 + 每周课时 + 免排时段）；支持批量导入（含工号唯一性校验，异常行行级提示）。
- **验收口径**：可增删改查教师主数据（新增 / 编辑 / 删除 / 查询）；工号重复或格式不合规时拒绝保存并提示；删除有任课记录的教师被拦截并提示引用关系（D16）；教师主数据删除与停用语义区分（退校教师保留主数据）；新增教师可一键开通 Teacher 账号（联动 REQ-AU-001）；可配置教师任课与约束；约束参与排课计算；教师信息与课表视图关联正确。

#### REQ-BD-006 场地 / 功能室管理 ｜ P0 ｜ Admin
- **做什么**：维护普通教室与功能室（音乐 / 美术 / 实验室等），纳入排课占用校验；**场地为独立主数据，名称受控录入（D20）**。
- **关键规则**：**场地与功能室合并为同一主数据，以「类型」字段区分（教室 / 功能室）**（D6**✅**）；功能室需排课占用，普通教室按班级固定；类型参与排课占用语义（功能室全校共享占用校验，普通教室班级专属）；班级人数 > 场地容量为**硬约束**，禁止排入并提示更换场地（D19**✅**）；**场地名称从受控命名列表选择或按既定格式新增（如「地理1」「音乐室2」），名称唯一，禁止无格式自由文本**（D20）。
- **交互与数据**：场地列表（名称 / 类型 / 容量 / 可用状态）+ 占用校验关联；类型下拉：教室 / 功能室；新增 / 编辑场地（受控件管理录入 + 名称查重）。
- **验收口径**：可维护场地主数据并按类型区分；新增 / 编辑场地名称违反受控格式或重名时拒绝并提示；排课时功能室参与占用校验、不被两个班级同节占用；场地占用冲突被实时拦截。

#### REQ-BD-007 合班课配置 ｜ P1 ｜ Admin
- **做什么**：配置多班合班、共用教师与场地的授课形式（如体育合班、大课）。
- **关键规则**：合班为**静态合并**，区别于走班；合班课共享同一教师与场地，占用同一节次时间槽；**合班名称为受控录入（D20）**，参与班级从受控班级列表多选（同年级 / 跨年级可配）。
- **接口与数据**：合班课配置（合班名称 / 参与班级多选 / 教师 / 场地 / 节次约束）。
- **验收口径**：可配置合班课（名称 / 参与班级 / 教师 / 场地 / 节次均受约束校验）；合班课在排课中作为一个排课单元占用时间与场地，且不产生班级 / 场地冲突提示。

### M2 智能自动排课（AP）

#### REQ-AP-001 一键智能排课 ｜ P0 ｜ Admin
- **做什么**：基于基础数据与约束规则，一键自动生成全校课表，**三类核心冲突为 0**（教师时间 / 班级同节多课 / 场地占用）；方案可预览 / 另存。
- **关键规则**：以学期 + 引用作息模板为排课上下文；排课结果为「排课方案」，遵循「方案(草稿) → 发布为正式课表 → 学期存档」状态机（D12**✅**），发布前可预览、微调、另存，每学期仅一份正式课表（覆盖旧方案前二次确认）；引擎对已锁定课程不覆盖（F008）；硬约束无法全满足时产出「冲突数 > 0 方案」+ **未排课时清单**（可跳转定位）并可保存继续手工调整（D14**✅**）。非功能：50 班排课 ≤5 秒（D3 验收边界）。
- **交互与数据**：工作台「一键排课」按钮 → 加载态「模拟排课计算中…」→ 结果（冲突数、完成时长）；排课方案列表（方案名 / 生成时间 / 冲突数 / 状态）。
- **验收口径**：生成方案三类核心冲突为 0；可预览并另存多套方案；可跑通**最小确定性验收样例**（2 班 + 2 教师 + 2 科目 + 1 功能室，连堂 / 禁排 / 免排约束 → 期望课表逐项满足且三类冲突为 0，D15**✅**）；无解 / 部分满足时输出未排课时清单且可跳转定位；50 班规模 ≤5 秒完成为验收边界。

> **D15 公共断言基准（最小确定性验收样例 · 期望课表逐格参照表）** — 已于 2026-09-17 09:36:00 获用户采纳（采纳 `10-V1.0交叉验证报告.md` §6 建议），作为排课引擎开发与验收的唯一公共同口径基准；用例层由 TC-AP-017 承接。
> - **基线**：时段 = 周一至周三，每天 4 节（第 1~4 节）；普通教室各 1 间归班，功能室 301 仅英语使用。
> - **课堂需求**：A 班 = 数学×2（张老师，连堂）+ 英语×1（李老师，301）；B 班 = 数学×2（李老师）+ 英语×1（张老师，301）。
> - **约束**：① 连堂：A 班数学 2 节连续（周一第 1+2 节）；② 禁排：英语禁排周三下午（第 3~4 节）；③ 免排：李老师 周二第 1 节免排、张老师 周三第 4 节免排。
> - **期望课表逐格参照表**（A/B 班各 3 天 × 4 节；「—」= 空闲）：

  | 时段 | 周一 A 班 | 周一 B 班 | 周二 A 班 | 周二 B 班 | 周三 A 班 | 周三 B 班 |
  |------|----------|----------|----------|----------|----------|----------|
  | 第 1 节 | 数学·张（连堂①） | 数学·李 | —（李免排） | — | — | 数学·李 |
  | 第 2 节 | 数学·张（连堂②） | — | — | — | — | — |
  | 第 3 节 | 英语·李（301） | — | — | 英语·张（301） | —（禁排） | —（禁排） |
  | 第 4 节 | — | — | — | — | —（禁排/张免排） | —（禁排） |

> - **判定（自检通过）**：张 = 周一第1节（A 数）+ 周一第2节（A 数，连堂②）+ 周二第3节（B 英，301）＝3 节，无教师时间冲突，周三第4节空（✓免排）；李 = 周一第1节（B 数）+ 周一第3节（A 英，301）+ 周三第1节（B 数）＝3 节，无教师时间冲突，周二第1节空（✓免排）；301 仅 周一第3节 / 周二第3节 两次占用、时段错开（✓场地占用为 0）；A/B 班均无同节多课；英语未出现在周三第3~4节（✓禁排）。三类核心冲突全为 0，期望课表逐项满足。

#### REQ-AP-002 课程预排与锁定 ｜ P1 ｜ Admin
- **做什么**：排课前手工预设固定课程（节次 / 教师 / 场地），排课引擎保留不覆盖；锁定后不可被自动调整（F008）。
- **关键规则**：锁定课程优先级高于自动分配；锁定后可解锁调整；**微调与拖拽调课中锁定课程均不可移动**（D13**✅**）。
- **交互与数据**：预排 / 锁定开关 + 课程锁定清单（课次 / 教师 / 班级 / 节次）。
- **验收口径**：排课前锁定的课程在自动排课后保持原地不被覆盖；解锁后恢复可自动调整。

#### REQ-AP-003 复杂场景适配排课 ｜ P1 ｜ Admin
- **做什么**：适配单双周、走班教学、跨年级授课三类复杂场景（F009）。

- **做什么**：教师 / 班级 / 场地三维度**全程实时校验**，违规禁止保存、槽位红色高亮，并**展示冲突明细、给出修改建议**；三类核心冲突零容忍（贯穿 M2 / M3）。

- **做什么**：全部主数据与操作遵循统一规则：增删改查、批量导入导出、撤销 / 重做、关键操作二次确认。
- **关键规则**：**关键操作枚举（D16**✅**）**＝删除类 / 发布 / 覆盖方案 / 切换学期 / 批量导入提交 / 学期存档 / 调课保存，均需二次确认；批量导入导出走统一模板与校验，**导入上限 5000 行/文件，超限拒绝并提示**（D19**✅**）；撤销 / 重做作用于可回滚操作；**被引用数据删除保护**：被学期引用的作息模板、有任课记录的教师 / 科目、被占用的场地，存在引用时禁止删除并提示引用关系；学期 / 模板删除不影响历史存档（D16）；并发场景采用「提示刷新 / 行级锁」弱并发控制（D19**✅**）。

- **交互与数据**：操作日志查询页（操作人 / 时间 / 模块 / 内容）；学期切换器；存档状态标记。
- **验收口径**：关键操作 100% 留痕可追溯；存档学期只读可导出不可修改；日志查询可按操作人 / 时间筛选。

- **做什么**：维护系统用户与角色，提供登录认证与角色权限判定（D11**✅**）；角色分 Admin（教务管理员）/ Teacher（普通教师）。

- **交互与数据**：用户管理（账号 / 姓名 / 角色 / 状态）+ 角色分配 + 登录 / 退出页。
- **验收口径**：可用 Admin / Teacher 双账号登录；教师登录后不可见非本人视图与管理入口；无权限访问被拒绝并提示；角色分配变更即时生效。
