## 1. 背景与目标

### 1.1 背景
学校手工排课耗时且极易出错（教师时间冲突、班级同节多课、场地撞车），教务管理员需要一套可投产的智能排课系统来替代手工排课：先维护基础数据与规则，再一键自动生成全校课表，全程兜底三类核心冲突为零，并支持多维度查看、拖拽调课、统计导出与学期存档。

### 1.2 产品目标
1. **核心排课闭环可投产**：V1.0 打通「基础数据 → 一键排课 → 方案(草稿)→发布→学期存档 → 多视图查看 → 拖拽调课 → 统计 → 导出打印」完整业务闭环，替代手工排课。
2. **冲突零容忍**：自动排课与手动调课全程由冲突校验引擎兜底，三类核心冲突（教师时间 / 班级同节多课 / 场地占用）为零（V-5）。
3. **口径可控可追溯**：主数据名称受控录入（D20）、关键操作二次确认与引用删除保护（D16）、操作日志全量留痕（D3）、需求/故事/用例/页面可全链上溯（§12）。
4. **验收有公共基准**：以 D15 最小确定性验收样例（期望课表逐格参照表）作为排课引擎开发与验收的唯一公共断言基准（附件 A）。

### 1.3 目标用户与角色
| 角色 | 说明 |
|------|------|
| 教务管理员（Admin） | 拥有系统全部配置、排课、调课、统计、导出打印、用户管理权限，可查看全校总课表 |
| 普通教师（Teacher） | 仅可查看本人课表、本人关联班级课表、查询本人空闲时段；无管理与导出打印入口 |

## 3. 功能清单（EARS · F↔REQ 1:1）

> EARS 句式：通用诵述 / 事件驱动 / 异常防护 / 状态驱动 / 可选功能。每条功能挂单条 REQ，1:1 对账无跳号（§13 自查第 2 项）；每条均带「做什么 / 关键规则 / 交互与数据 / 验收口径」。

### F1 学期管理 ｜ 挂 REQ-BD-001 ｜ P0 ｜ Admin

- **做什么**：系统应维护学期主数据，作为排课与数据归集的时间单元；应支持多学期独立存档、一键切换当前学期。
- **关键规则**（事件驱动）：每个学期仅引用一个作息模板（D4）；当新增学期时，系统应强制其绑定一个现有作息模板，未绑定的学期不得进入一键排课（D8）；当切换学期时，该学期引用的作息模板随之生效；学期状态枚举＝未开始 / 进行中 / 已结束 / 已存档（D12）；当学期已存档时，应只读可导出。
- **交互与数据**：学期列表（学期 / 学年 / 起止日期 / 引用作息模板 / 状态）；新增学期下拉必选作息模板；支持批量导入。
- **验收口径**：可新增 / 编辑 / 切换学期并绑定任一现有作息模板；未绑定作息模板的学期不可触发一键排课；切换学期不发生跨学期串扰；已存档学期不可编辑、可查看导出。

### F2 作息模板 ｜ 挂 REQ-BD-002 ｜ P0 ｜ Admin

- **做什么**：系统应维护作息模板独立主数据，支持配置多个版本，定义开放星期与每节起止时间。
- **关键规则**（事件驱动）：当编辑保存模板时，系统应生成新版本（v2/v3…），历史版本保持原样（版本快照）；模板与学期解耦（D4），同一模板可被多个学期同时引用；修改模板不应回改已引用该模板的历史学期已生成课表数据。
- **交互与数据**：模板列表 + 版本记录（v1/v2/v3）；模板编辑表单（模板名称、基于版本、开放排课星期、节次时间表「第 1 节 08:00-08:45 …」）；保存即生成新版本。
- **验收口径**：可创建模板并配置节次 / 开放星期；同一模板可被多个学期引用；修改模板不影响历史学期已生成课表数据（版本快照生效）。

### F3 班级 / 年级管理 ｜ 挂 REQ-BD-003 ｜ P0 ｜ Admin

- **做什么**：系统应维护年级-班级-班主任-人数的组织数据；年级为独立可管理实体，班级归属年级。
- **关键规则**（异常防护）：当新增 / 编辑班级时，系统应校验班级名称格式——自动按「年级（序号）班」生成（如「高一（1）班」），序号为 1-99 整数受控录入，禁止自由文本直接输入班级名（D20）；当序号超出 1-99 或非整数时，保存应被拒绝并提示；当删除被班级引用的年级时，应受引用保护并提示引用关系（D16）。
- **交互与数据**：年级区（受控名称列表：高一/高二/高三 或 七年级…九年级，支持增删改）+ 班级列表（班级名称 / 所属年级 / 班主任 / 人数）增删改查；新增班级＝选择所属年级 + 输入受控序号，系统自动生成规范名称；批量导入按统一命名规范校验，违反规范行级报错。
- **验收口径**：可独立增删改查年级；新增 / 编辑班级输入不符合「年级（序号）班」格式或序号超出 1-99 被拒绝并提示；删除被班级引用的年级受引用保护提示；批量导入异常行给出行号级提示。

### F4 科目与课时规则 ｜ 挂 REQ-BD-004 ｜ P0 ｜ Admin

- **做什么**：系统应维护科目主数据及每周课时规则（每周课时、时段优先、连堂偏好、禁排规则），作为排课引擎约束输入。
- **关键规则**（可选用法）：系统应提供课时均衡 / 上下午均衡 / 固定时段强制空课或指定课程三类可配约束项，默认关闭，启用后作为软约束参与排课（D17）；当新增 / 编辑科目时，系统应执行名称受控校验，禁止同义不同名并存（如「语」「语文课」）（D20）；当配置产生规则冲突时，系统应明确提示而非静默忽略。
- **交互与数据**：科目列表 + 课时规则编辑（每周课时、连堂偏好、禁排时段、时段优先）；新增 / 编辑科目名称与课时规则。
- **验收口径**：可配置科目每周课时与约束；新增 / 编辑科目名称违反受控规范时录入被拒绝；排课引擎按规则约束产出，规则冲突时给出明确提示。

### F5 教师信息与任课约束 ｜ 挂 REQ-BD-005 ｜ P0 ｜ Admin

- **做什么**：系统应维护教师主数据实体（完整增删改查），并维护教师-科目-班级-场地的任课约束与免排/禁排/课时数/连堂偏好等配套约束。
- **关键规则**（异常防护 / 事件驱动）：当提交教师工号时，系统应校验格式为「T + 数字」且唯一，重复或不合规时拒绝保存并提示（D20）；当新增教师并勾选「一键开通登录账号」时，系统应生成对应 Teacher 账号，可登录（联动 F20）；当删除有任课/关联记录的教师时，应受 D16 引用保护并提示引用关系；教师主数据「删除」与「停用」语义区分（退校教师保留主数据）；任课约束为基础数据而非排课结果；免排（主动配置）与禁排（业务规则限定）语义区分。
- **交互与数据**：教师列表（工号 / 姓名 / 性别 / 手机 / 状态）+ 增删改查入口 + 查询；新增 / 编辑教师表单（工号受控、姓名、性别、手机、进退校状态、一键开通登录账号开关）；任课配置表单（教师 → 科目 + 班级 + 场地 + 每周课时 + 免排时段）；批量导入（工号唯一性校验，异常行行级提示）。
- **验收口径**：可增删改查教师主数据；工号重复或格式不合规时拒绝保存并提示；删除有任课记录的教师被拦截并提示引用关系；删除与停用语义区分；新增教师可一键开通 Teacher 账号；约束参与排课计算；教师信息与课表视图关联正确。

### F6 场地 / 功能室管理 ｜ 挂 REQ-BD-006 ｜ P0 ｜ Admin

- **做什么**：系统应维护普通教室与功能室（音乐 / 美术 / 实验室等），纳入排课占用校验。
- **关键规则**（异常防护）：场地与功能室合并为同一主数据，以「类型」字段区分（教室 / 功能室）（D6）；当班级人数大于目标场地容量时，系统应执行硬约束禁止排入并提示更换场地（D19）；当新增 / 编辑场地名称违反受控格式或重名时，应拒绝并提示（D20，如「地理1」「音乐室2」）。
- **交互与数据**：场地列表（名称 / 类型 / 容量 / 可用状态）+ 占用校验关联；类型下拉：教室 / 功能室；新增 / 编辑场地（名称查重）。
- **验收口径**：可维护场地主数据并按类型区分；名称违反受控格式或重名时拒绝并提示；排课时功能室参与占用校验（全校共享）、不被两个班级同节占用；容量超限被硬约束拦截。

### F7 合班课配置 ｜ 挂 REQ-BD-007 ｜ P1 ｜ Admin

- **做什么**：系统应支持配置多班合班（共用教师与场地的授课形式），合班为静态合并、区别于走班。
- **关键规则**（异常防护）：当提交合班课配置（合班名称受控 / 参与班级多选 / 教师 / 场地 / 节次约束）时，任一非法则拒绝并提示（D20）；合班课不限科目，任意科目可配置（D10）；合班课在排课中作为一个排课单元占用时间与场地。
- **交互与数据**：合班课配置（合班名称 / 参与班级多选 / 教师 / 场地 / 节次约束）。
- **验收口径**：可配置合班课（名称 / 参与班级 / 教师 / 场地 / 节次均受约束校验）；合班课作为排课单元占用时间与场地，不产生班级 / 场地冲突提示。

### F8 一键智能排课 ｜ 挂 REQ-AP-001 ｜ P0 ｜ Admin

- **做什么**：系统应基于「学期 + 引用作息模板」一键自动生成全校课表，三类核心冲突为 0；方案可预览 / 另存。
- **关键规则**（状态驱动 / 异常防护）：排课结果遵循「方案(草稿) → 发布为正式课表 → 学期存档」状态机，发布前可预览、微调、另存，每学期仅一份正式课表，覆盖旧方案前二次确认（D12）；引擎对已锁定课程不覆盖（F9）；当硬约束无法全部满足时，系统应产出「冲突数 > 0 方案」并列出**未排课时清单**（可跳转定位），允许保存继续手工调整（D14）；系统应可跑通**最小确定性验收样例**（2 班 + 2 教师 + 2 科目 + 1 功能室，连堂 / 禁排 / 免排约束 → 期望课表逐项满足且三类冲突为 0，D15，附件 A）；50 班规模 ≤5 秒完成（D3 / V-1）。
- **交互与数据**：工作台「一键排课」按钮 → 加载态「模拟排课计算中…」→ 结果（冲突数、完成时长）；排课方案列表（方案名 / 生成时间 / 冲突数 / 状态）。
- **验收口径**：生成方案三类核心冲突为 0；可预览并另存多套方案；可跑通 D15 最小确定性验收样例（附件 A）；无解 / 部分满足时输出未排课时清单且可跳转定位；50 班规模 ≤5 秒完成为验收边界。

### F9 课程预排与锁定 ｜ 挂 REQ-AP-002 ｜ P1 ｜ Admin

- **做什么**：系统应支持排课前手工预设固定课程（节次 / 教师 / 场地），排课引擎保留不覆盖。
- **关键规则**（状态驱动）：锁定课程优先级高于自动分配；在自动排课、「方案微调」与拖拽调课中，锁定课程均不可移动（D13）；锁定后可解锁，解锁后恢复可自动调整。
- **交互与数据**：预排 / 锁定开关 + 课程锁定清单（课次 / 教师 / 班级 / 节次）。
- **验收口径**：排课前锁定的课程在自动排课后保持原地不被覆盖；解锁后恢复可自动调整；微调 / 拖拽调课中锁定课程不可移动并提示。

### F10 复杂场景适配排课 ｜ 挂 REQ-AP-003 ｜ P1 ｜ Admin

- **做什么**：系统应适配单双周、走班教学、跨年级授课三类复杂场景。
- **关键规则**（通述）：单双周为相邻两周整周课表结构轮换（单周课表 / 双周课表），学期第 1 周按单周启动、按周序号奇偶轮换，遇节假日停课周不顺延周次（D18）；走班按所选科目跨班到指定场地上课（场地 + 教师双重分配），按基线实现、深化留 V2.0（D9）；跨年级授课放开教师年级限制、不产生跨年级班级冲突。
- **交互与数据**：排课前配置单双周启用开关、走班科目与目标场地、跨年级任课标记；排课结果在对应视图体现周次差异。
- **验收口径**：开启单双周后能生成单 / 双周两套课表并正确轮换；走班课程占用目标场地且不冲突；跨年级任课教师课时统计正确。

### F11 多维度课表视图 ｜ 挂 REQ-AT-001 ｜ P0 ｜ Admin / Teacher

- **做什么**：系统应提供班级 / 教师 / 全校 / 场地 / 任课五类维度课表视图，按角色限权。
- **关键规则**（可选功能）：管理员可见全部视图；普通教师仅可见本人课表、本人关联班级课表（角色权限边界，D11）；全校总课表为管理员视角；视图可随学期切换，不发生跨学期数据串扰。
- **交互与数据**：视图切换 Tab + 周课表网格（节次 × 星期，课程块含科目 / 教师 / 班级 / 场地）；可按学期切换。
- **验收口径**：五视图可正确切换且内容与维度一致；教师登录看不到非本人视图与管理入口；切换学期展示对应学期课表。

### F12 拖拽可视化调课 ｜ 挂 REQ-AT-002 ｜ P0 ｜ Admin

- **做什么**：系统应支持在课表视图中拖拽课程块到新节次 / 场地完成调课，实时冲突校验。
- **关键规则**（异常防护）：拖放前实时校验三类核心冲突；冲突目标槽位禁止放置并红色高亮 + Toast 提示；调课支持撤销 / 重做（可成组批量）；「方案微调」复用本拖拽调课能力（同一实时冲突校验与撤销 / 重做规则，D13）；调课保存触发二次确认并记日志（D16）。
- **交互与数据**：课表网格课程块可拖拽；落位触发冲突校验 Toast；撤销 / 重做按钮；关键调课操作二次确认。
- **验收口径**：合法调课可保存并更新视图；冲突调课被拦截提示；撤销 / 重做正确回退 / 重放操作序列；保存二次确认生效。

### F13 空闲时段查询 ｜ 挂 REQ-AT-003 ｜ P1 ｜ Teacher(仅本人) / Admin

- **做什么**：系统应支持查询某教师 / 班级空闲可用节次，用于调课决策。
- **关键规则**（异常防护）：普通教师仅可查询本人空闲时段（D11）；管理员可查询任意教师 / 班级；查询结果与当前课表数据一致。
- **交互与数据**：空闲时段查询表单（对象 → 周次）→ 以课表网格高亮空闲槽位。
- **验收口径**：教师仅能查询本人结果；管理员可查任意对象；空闲槽位展示准确且与当前课表一致。

### F14 教师工作量统计 ｜ 挂 REQ-AS-001 ｜ P1 ｜ Admin

- **做什么**：系统应支持按周 / 学期统计教师课时，分常规 / 连堂 / 合班 / 加班四类。
- **关键规则**（通述）：连堂 / 合班 / 加班为加计类型，不与常规重复统计（连堂按节次、合班按 1 节）；加班判定细则 V1.1 细化（D7 / Q3），V1.0 展示四类字段与基础口径、加班列占位。
- **交互与数据**：工作量统计表（教师 / 常规 / 连堂 / 合班 / 加班 / 周汇总 / 学期汇总）；周 / 学期口径切换；支持导出（联动 F15）。
- **验收口径**：统计结果与系统内课表数据一致；四类口径字段齐全且加计不重复；周 / 学期汇总准确。

### F15 全维度 Excel 导出 ｜ 挂 REQ-EX-001 ｜ P0 ｜ Admin

- **做什么**：系统应支持基础数据 / 课表 / 统计全维度 Excel 导出。
- **关键规则**（通述）：导出字段与系统内部字段逐字段一致；1000 条批量导出 ≤3 秒（D3 / V-2）。
- **交互与数据**：导出面板（维度选择：基础数据 / 课表 / 统计 → 学期 → 导出）；导出文件按维度命名。
- **验收口径**：各维度导出字段与系统展示口径一致；导出文件可正常打开且数值与系统一致；1000 条批量导出 ≤3 秒。

### F16 自定义模板打印 ｜ 挂 REQ-EX-002 ｜ P1 ｜ Admin

- **做什么**：系统应支持自定义打印模板（纸张 / 版式 / 校徽），输出可印发课表。
- **关键规则**（通述）：预设常用版式；支持校徽 / 标题等自定义；打印预览所见即所得。
- **交互与数据**：模板管理（模板列表 / 新建 / 套用）+ 打印预览页。
- **验收口径**：可按所选班级 / 教师课表以自定义模板打印；预览与打印结果一致。

### F17 冲突校验引擎 ｜ 挂 REQ-CE-001 ｜ P0 ｜ 全局

- **做什么**：系统应于自动排课与手动调课全程对教师 / 班级 / 场地三维度进行实时冲突校验，违规禁止保存、槽位红色高亮，并展示冲突明细与修改建议。
- **关键规则**（异常防护 / 可选功能）：三类核心冲突（教师时间 / 班级同节多课 / 场地占用）零容忍（V-5）；当冲突由前面的排课限制（约束 / 配置）引发时，系统应提供双处置路径（D21）：**① 只本次忽略**——仅本次排课放行通过、不修改系统配置、后续排课仍按系统设置的规则执行（豁免不落库为全局规则，不计为静默冲突）；**② 去修改配置**——跳转对应配置维护入口修改约束后重新排课。
- **交互与数据**：冲突提示 Toast / 槽位红色高亮 / 冲突明细清单（冲突类型 / 涉及对象 / 节次 + 修改建议）/「只本次忽略」「去修改配置」处置入口与二次确认。
- **验收口径**：引擎产出结果三类核心冲突为 0（用户显式选择「只本次忽略」属人工豁免路径、不计为静默冲突，仅本次排课生效、不改系统配置）；冲突明细与修改建议可见、可据其定位；「只本次忽略」后续排课仍按系统设置执行；「去修改配置」可跳转对应配置维护入口。

### F18 数据通用规则引擎 ｜ 挂 REQ-CM-001 ｜ P0 ｜ Admin

- **做什么**：系统应使全部主数据与操作遵循统一规则：增删改查、批量导入导出、撤销 / 重做、关键操作二次确认。
- **关键规则**（异常防护）：关键操作枚举（D16）＝删除类 / 发布 / 覆盖方案 / 切换学期 / 批量导入提交 / 学期存档 / 调课保存，均需二次确认；批量导入导出走统一模板与校验，导入上限 5000 行 / 文件、超限拒绝并提示（D19 / V-4）；被引用数据删除保护（被学期引用的作息模板、有任课记录的教师 / 科目、被占用的场地存在引用时禁止删除并提示引用关系）；学期 / 模板删除不影响历史存档；并发场景采用「提示刷新 / 行级锁」弱并发控制（D19）。
- **交互与数据**：统一操作组件（确认对话框 / 撤销重做按钮 / 批量导入模板与异常行提示）。
- **验收口径**：关键操作有二次确认；导入超限被拒绝并提示、异常行级提示；被引用数据禁止删除并提示引用关系；撤销 / 重做行为符合预期。

### F19 操作日志与多学期存档 ｜ 挂 REQ-LG-001 ｜ P0 ｜ Admin

- **做什么**：系统应记录操作人 / 时间 / 内容的完整留痕，可追溯；学期数据可按学期存档，存档后只读可导出。
- **关键规则**（状态驱动）：关键操作（枚举见 F18）全量记录日志；操作日志永久留存（D3 / V-3）；发布 / 存档 / 切换学期等状态流转全量纳入留痕（D12）；多学期数据独立存档、互不串扰。
- **交互与数据**：操作日志查询页（操作人 / 时间 / 模块 / 内容）；学期切换器；存档状态标记。
- **验收口径**：关键操作 100% 留痕可追溯；存档学期只读可导出不可修改；日志查询可按操作人 / 时间筛选；日志永久留存不被清理。

### F20 用户与角色管理 ｜ 挂 REQ-AU-001 ｜ P0 ｜ Admin / Teacher

- **做什么**：系统应维护用户与角色，提供登录认证与角色权限判定（双角色：Admin / Teacher）。
- **关键规则**（事件驱动）：本地账号体系（浏览器 Web 应用内维护，无外部对接，D5）；系统内置默认管理员初始化；Admin 拥有系统全部权限，Teacher 仅本人课表 / 本人关联班级课表 / 本人空闲时段查询（D11）；权限判定贯穿 F11 / F13 / F12（仅 Admin）；角色分配变更即时生效；新增教师可一键开通 Teacher 账号（联动 F5，D20）。
- **交互与数据**：用户管理（账号 / 姓名 / 角色 / 状态）+ 角色分配 + 登录 / 退出页。
- **验收口径**：可用 Admin / Teacher 双账号登录；教师登录后不可见非本人视图与管理入口；无权限访问被拒绝并提示；角色分配变更即时生效。
