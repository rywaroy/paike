### 1.2 静态核验结论（一句话）

- **PRD 行为口径总体完备**：78 条中 47 条无需补模型即可执行；D15 公共基准自洽；D21 双路径、D16 七类确认、D19 容量/导入上限均有一致口径。
- **主要风险不在需求，而在实现蓝图**：28 条因 DDD 缺实体/命令/不变式而无法直接实现，集中在模板版本、方案覆盖、未排课时/冲突明细、单双周、走班、撤销重做、账号 CRUD、导入契约。
- **原型不能作为可执行基线**：原型中大量能力是 Toast/模拟/硬编码；且存在教师导航 `TypeError`、菜单误隐藏、重复 modal id 等缺陷。原型偏离不等于需求冲突，按 PRD 实现。
- **5 项人工参数已落定**：并发采用乐观版本+刷新提示，认证采用最小安全基线，性能采用固定数据集+服务端 p95，数据交换采用 XLSX+固定模板+服务端 PDF，节假日采用停课周占序号且奇偶推进。原阻塞标记已解除。

### 3.3 原型偏离（不代表需求冲突）

原型是交互设计参考，不是生产代码。已确认的偏离包括但不限于：

1. `loginAs('teacher')` 调用 `nav('P13','mine')` 时，`$('#navP13T')` 被当作 id 传给 `getElementById`，返回 `null`，触发 `TypeError`。
2. `applyRoleUI()` 对“我的课表”项要求 `data-nav`，但该项只有 `id="navP13T"`、无 `data-nav`，导致教师端“我的课表”被隐藏，只剩 P15。
3. `mIgnoreOnce` 模态 id 重复定义两次。
4. `delProtected()` 打开后立即关闭 `mArchive`，只弹 Toast。
5. `saveClass()` 编辑时改年级，把记录写入新年级数组的旧索引，旧记录残留。
6. `saveGrade()` 重命名年级时批量改写班级名，可能破坏引用。
7. `delTeacher()` 检查 `t[6]`，现有教师记录只有 0-5 索引，引用保护失效。
8. `saveTeacher()` 允许修改已禁用的工号字段。
9. P08 使用“检修中”，与 DDD UL 的场地状态“可用/停用”不一致。
10. P09 合班课表单含科目字段，PRD 交互与 DDD `CombinedClass` 均未要求。
11. P11 锁定/解锁按钮无事件处理。
12. P12 单双周开关仅 Toast，不生成两套课表。
13. P13 五个 Tab 渲染同一份班级课表。
14. P14 冲突仅对“理化生 + data-d=2”硬编码；撤销/重做未真正实现。
15. P15 空闲查询固定返回第 1/4 节。
16. P16-P21 多处仅静态展示或 Toast：统计、导出、打印、日志筛选、用户/角色、新用户。
17. P10 方案名“2026秋-v4（最新）”与 P02 日志“2026秋-v3”不一致。
18. `runAutoSchedule()` 永远以 0 冲突结束；`simNoSolution()` 硬编码 3 冲突/6 未排课时。

> 处理原则：不把原型缺陷写成需求；生产实现以 PRD 为准；原型仅用于页面结构与交互参考（A-22）。
