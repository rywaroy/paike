## 4. 三个关键个案说明

### 4.1 TC-BD-004：不是“缺测试数据”，而是规约关闭了该状态

D8 与 `CreateSemester` 的前置条件共同保证：**任何正常创建的学期都必然绑定模板**。因此“未绑定模板的学期”只能来自：

1. 历史数据迁移；
2. 直接改库/导入绕过应用层；
3. 系统缺陷导致的不变量破坏。

若产品确认 V1.0 无历史迁移，则本条不应作为用户路径测试保留。建议改写为**接口防御性测试**：直接以 `scheduleTemplateId = null` 调用排课接口，断言返回明确错误而非崩溃。该改写不改变 09 原文，只在执行计划中作为派生用例登记。

### 4.2 TC-BD-008：可由 A-08 的最小规则集关闭

本条不是“无法定义”，而是“尚未定义”。建议在 A-08（模板版本与学期钉扎）中增补以下最小规则，即可转为可验证：

- 节次编号从 1 开始连续，不允许跳号/重复；
- 单节 `startTime < endTime`；
- 同一开放星期内节次时间段不重叠；
- 所有节次落在 `00:00–24:00`；
- `openWeekdays` 为非空的星期一至星期日子集。

> 这些规则是模板数据的最低一致性要求，不引入新的业务偏好；若产品认为应允许“上午/下午分段编号”等特殊编排，需在 A-08 中显式说明，否则按上述规则执行。

### 4.3 TC-AP-016：应移出系统测试，不应“执行后通过”

该条断言的是版本边界（V1.0 不含动态走班编排），不是系统行为。任何“执行通过”的结论都只是文档核对，不是测试结论。建议：

- 从测试执行集移出；
- 保留在 09 原文；
- 在发布评审中以“范围核对项”确认；
- 不与 89 条的通过率混算。

## 6. 处置原则

1. **不删除**：17 条孤儿记录全部保留可追溯；09 原文不动。
2. **不掩盖**：任何包含孤儿子断言的 TC，不得整体标记为“通过”；主断言通过只能证明主断言。
3. **不擅自补规则**：除本文件明确建议的 A-08 最小规则外，不由测试侧自行发明业务规则来“救活”用例。
4. **人工优先**：H-01~H-05 已于 2026-10-19 落定；相关孤儿恢复为可执行，但在实际执行前一律记为“未执行”，不得预填通过。
5. **范围项隔离**：OR-AP-016 作为范围核对项，不计入测试通过率。
