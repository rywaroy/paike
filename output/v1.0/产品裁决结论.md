### 1.1 效力规则

1. **PRD 是行为与验收的唯一规范源**；原型与 DDD 只提供实现参考。
2. 原型与 PRD 不一致时，**按 PRD 实现**，原型缺陷不进入需求。
3. DDD 与 PRD 不一致时，**以 PRD 为准补模型**（§5），不得以“DDD 没有”为由削减 PRD 能力。
4. D3-D21 与 PRD 一致的继续有效；不一致处已在 §3 标注，并按 PRD 执行。
5. 09 是测试意图载体，不是需求源；其预期结果与 PRD 冲突时，以 PRD 为准。

## 4. 产品裁决 A-01 ~ A-22

### 4.1 状态与枚举

#### A-01 学期状态四值

- **疑问**：PRD F1 规定「未开始 / 进行中 / 已结束 / 已存档」四值；DDD `Semester.stateModeling` 称“状态字段只存三个存储态，已结束为展示派生”，未明确第四个如何存储。
- **证据**：PRD F1、§5；DDD `Semester.stateModeling`、R-002、R-046。
- **裁决**：
  1. **对外（UI/API/导出/筛选）永远是四值**，任何接口不得返回第五值或空值。
  2. 存储可以采用“日期派生 + 已存档显式标记”的实现：`未开始/进行中/已结束` 由起止日期与当前日期计算，`已存档` 为持久化状态。
  3. 已存档是**终态**：即使日期变化也不得回到进行中/已结束；解除存档不在 V1.0 范围。
  4. 学期状态只由日期与存档命令驱动，不允许手工直接改。
- **影响**：TC-BD-002；M-15。
- **理由**：PRD 高于 DDD；派生实现不改变对外语义，且能兼容 DDD 的 DataOnly 设计。

#### A-02 教师状态与“停用/退校”

- **疑问**：PRD F5 要求区分“删除”与“停用”，并写“退校教师保留主数据”；DDD 的 UL 用「在职/退校」，`stateModeling` 用「在职/停用」；09 TC-BD-021 写“执行停用/退校后状态为退校”。三处术语混用。
- **证据**：PRD F5；DDD `Teacher` 聚合与 `stateModeling`；09 TC-BD-021。
- **裁决**：
  1. `Teacher.status` 的业务枚举固定为 **在职 / 退校** 二值，不再引入第三个“停用”值。
  2. **“停用教师”= 把状态置为退校**（业务停用），保留主数据与历史引用；可“复职”回在职。
  3. **“删除教师”= 仅在无任何引用时允许物理/逻辑删除**；有任课、班主任、账号等引用时拒绝（D16）。删除与停用是两条不同路径。
  4. `Account.status` 独立为 **启用 / 停用**；教师退校时联动停用其账号（M-22），复职不自动启用账号，需管理员显式开启。
- **影响**：TC-BD-021；M-15/M-22。
- **理由**：PRD 的“删除/停用区分”是业务语义；把“停用”落到“退校”可消除 DDD 内部不一致，同时保留账号独立状态。

#### A-03 场地类型与状态

- **疑问**：DDD `Venue` 为类型「教室/功能室」、状态「可用/停用」；原型 P08 出现“检修中”，可能被实现为第三状态或第三类型。
- **证据**：PRD F6/D6；DDD `Venue`；原型 P08。
- **裁决**：
  1. `type` 严格二值：**教室 / 功能室**，不得新增第三类型。
  2. `status` 严格二值：**可用 / 停用**；停用即不参与排课占用。
  3. “检修中”不是枚举值，只能作为**停用原因/备注**保存；历史数据中的“检修中”在迁移时映射为 `停用 + remark=检修中`。
- **影响**：TC-BD-029。
- **理由**：D6 明确合并类型；原型是交互参考，不得扩展枚举。

### 4.2 主数据、命名与删除

#### A-04 合班课的科目字段

- **疑问**：原型 P09 的合班表单含“科目”；PRD D10 写“合班课不限科目，任意科目可配置”；DDD `CombinedClass` 无 `subjectId`。三者表述不一致。
- **证据**：PRD F7/D10；DDD `CombinedClass`；原型 P09。
- **裁决**：
  1. `CombinedClass` **不持久化 `subjectId`**，科目不是合班的必填属性，也不参与合班合法性校验。
  2. 若页面需要展示科目，只能从参与班级的任课记录**派生展示**，可为“多科目/未指定”，只读。
  3. 合班的合法性只校验：名称受控、参与班级非空且存在、教师存在、场地存在、节次约束合法。
- **影响**：TC-BD-030；M-18。
- **理由**：D10 的本意是“合班不受科目限制”；把科目做成字段反而制造了不必要的约束与数据不一致。

#### A-05 受控命名与词表

- **疑问**：D20 要求班级、科目、场地、合班名称受控；DDD R-006/007/014/017 只有文字规则，没有词表实体；原型部分输入仍可自由文本；PRD §6 引用的 `02-名词统一.md` 在输入目录中缺失。
- **证据**：PRD F3-F7/D20、§6；DDD R-006/007/014/017；05 审查建议 014；输入目录文件清单。
- **裁决**：
  1. 班级名**只能生成**：`年级名（序号）班`，序号 1-99 整数；不提供自由文本入口。
  2. 教师工号**只能** `T + 数字`，全局唯一；编辑时工号不可改（避免账号关联漂移）。
  3. 科目、场地、合班名称必须命中**运行期受控词表**（数据库表，可在不重新部署的情况下维护）；同义词表命中即视为重复。
  4. 名称比较前做归一化：去首尾空格、全角转半角、大小写不敏感、去除内部连续空白；归一化后重名拒绝。
  5. `02-名词统一.md` 缺失不阻塞开发：V1.0 以“可配置词表 + PRD 示例种子数据”实现；正式上线的完整词表由产品/教务以数据方式提供，属于数据准备，不是代码阻塞。
  6. 受控词表的维护入口在 V1.0 不做独立页面；通过初始化数据/管理配置维护，校验逻辑必须存在。
- **影响**：TC-BD-011/012/014/015/019/027；M-23。
- **理由**：D20 的核心是“不能随意输入”，不是“必须有一个词表管理页”；用可配置表即可满足，且避免凭空发明 UI。

#### A-06 账号唯一键

- **疑问**：09 TC-BD-023 写“手机号/工号”唯一；DDD `Account.username` 唯一，`Teacher.phone` 无唯一约束；PRD F20 只说本地账号。
- **证据**：PRD F5/F20/D11；DDD `Account`；09 TC-BD-023。
- **裁决**：
  1. 教师账号的登录名 **= 教师工号**，全局唯一；不允许用手机号登录。
  2. 手机号只是联系方式，不唯一、不作为登录键。
  3. 管理员用户名由初始化配置决定（默认 `admin`，凭据交付方式见 H-02）；同样按 `username` 全局唯一。
  4. 同一教师重复开通账号必须**幂等**：返回既有账号或明确拒绝，不产生第二条；以 `teacherId` 做唯一关联。
  5. 用户名比较做大小写不敏感归一化，但展示保留原样。
- **影响**：TC-BD-023；M-09。
- **理由**：工号已是教师主数据的唯一业务键，复用它避免第二套唯一性规则；手机号会变更，不适合做登录键。

#### A-17 删除、停用与存档保护

- **疑问**：PRD F18 同时写“被引用数据禁止删除”和“学期/模板删除不影响历史存档”；DDD `DeleteSemester` 前置“学期未被引用”语义不清，且没有 `DeleteScheduleTemplate`；TC-CM-003 需要一个“允许删除”的正向路径。
- **证据**：PRD F18/D16；DDD R-036/R-037、`DeleteSemester`；09 TC-CM-003。
- **裁决**：
  1. **引用保护优先**：被当前/历史数据引用的主数据不得物理删除，只能停用/退校/逻辑停用；提示具体引用关系。
  2. **学期删除**：仅允许删除「未开始、无方案、无日志、非当前」的学期；进行中/已结束/已存档学期不得删除。已存档学期必须始终可查询、可导出。
  3. **模板删除**：按“模板版本”判定；某版本被任一学期钉扎或任一方案引用时，拒绝删除；未被引用的版本可逻辑删除并从新选择列表中隐藏。
  4. **删除允许时的存档验证**：删除一个未被引用的学期/模板版本后，**其他**已存档学期的课表与日志必须逐字段不变（TC-CM-003 的正向路径）。
  5. 所有删除均为逻辑删除（`deletedAt`/`deletedBy`），列表默认过滤；审计需要时仍可追溯。
  6. 停用/退校不受引用保护限制，但必须保留历史展示所需字段。
- **影响**：TC-CM-002/003；M-14。
- **理由**：这样同时满足 D16 的引用保护与“删除不影响历史存档”，并给 TC-CM-003 一个可构造的正向场景（删除未被引用项，验证其他存档不受影响）。

### 4.3 数据交换

#### A-07 批量导入的事务与计数

- **疑问**：PRD V-4/D19 规定 >5000 行整份拒绝；TC-BD-013/025/CM-005 要求 ≤5000 行时“非法行跳过、合法行入库”；DDD 无导入模型；05 审查建议 009 未决“部分成功 vs 整体回滚”。
- **证据**：PRD V-4/F18；DDD R-038；05 建议 009；09 TC-BD-013/025/CM-004/005。
- **裁决**：
  1. **行计数**：数据行数，不含表头与空行；以文件解析后的逻辑行为准。
  2. **>5000 行**：整份文件拒绝，**零写入**，返回超限行数与上限；不得只导入前 5000 行。
  3. **≤5000 行**：逐行校验；合法行提交，非法行跳过；返回总数/成功数/失败数/每行错误（行号、字段、原因）。
  4. **重复键**（工号、班级名等）按非法行处理，不做 upsert；提示“已存在”。
  5. **事务边界**：合法行作为一个批次提交；若数据库/基础设施在提交中失败，整批回滚；业务校验失败**不**回滚其他合法行。
  6. 导入任务记录保留：文件名、操作人、时间、总数、成功/失败数、错误明细，供追溯。
- **影响**：TC-BD-013/025、TC-CM-004/005；M-08。
- **理由**：PRD 明确“超限拒绝、不能悄悄只导一部分”，而“非法行跳过”是行级语义；两者用“文件级上限 + 行级校验”即可同时满足。

### 4.4 模板与方案

#### A-08 模板版本、学期钉扎与节次校验

- **疑问**：PRD F2 要求 v1/v2/v3 快照、历史版本不变、历史学期不受影响；DDD `ScheduleTemplate` 只有 `version` 标量，无版本实体；TC-BD-008 要求“节次重叠/超界/非法开放星期”被拒绝，但未定义合法规则；TC-BD-004 依赖“未绑定模板的学期”，与 D8 冲突。
- **证据**：PRD F2/D4/D8；DDD `ScheduleTemplate`；09 TC-BD-004/006/007/008。
- **裁决**：
  1. `ScheduleTemplate` 是稳定身份；新增 `ScheduleTemplateVersion` 不可变快照：`versionNo`、`periods[]`（periodNo/start/end）、`openWeekdays[]`、`createdAt`、`createdBy`。
  2. 编辑保存 = 追加新版本，**绝不修改旧版本**；版本号单调递增。
  3. 学期在创建时钉扎 `scheduleTemplateVersionId`；后续模板新版本**不自动影响**已建学期。
  4. 学期生成方案后，不允许更换模板版本（避免课表与时间框架不一致）；生成前可更换，需二次确认。
  5. **节次合法性最小规则**（用于关闭 TC-BD-008）：
     - 节次编号从 1 开始连续，不允许跳号/重复；
     - 每节 `startTime < endTime`；
     - 同一开放星期内节次时间段不重叠；
     - 所有节次落在 `00:00–24:00`；
     - `openWeekdays` 为星期一至星期日的非空子集。
  6. **TC-BD-004 处置**：D8 使“未绑定模板的学期”在正常路径不可达。本条不删除，但**退役为派生防御性测试**：直接以空 `scheduleTemplateVersionId` 调用排课接口，断言明确拒绝。不得为了测试放宽 D8。
- **影响**：TC-BD-006/007/008、OR-BD-004；M-01。
- **理由**：PRD 的“版本快照”在 DDD 中只有标量，必须补实体；节次规则是模板数据的最低一致性要求，不引入业务偏好。

#### A-09 发布覆盖与唯一正式课表

- **疑问**：PRD D12/§5 要求每学期仅一份正式课表、覆盖需二次确认；DDD `TimetablePlanLifecycle` 只有 `Draft → Published → Archived`，无覆盖迁移、无唯一性不变式，也无“另存”命令。
- **证据**：PRD F8/D12/§5；DDD 状态机、`PublishPlan`；09 TC-AP-005/006。
- **裁决**：
  1. 方案状态扩展为：**Draft（草稿）/ Published（正式）/ Superseded（被覆盖）/ Archived（已存档）**。
  2. **唯一不变式**：同一学期任意时刻至多 1 个 `Published`。
  3. 发布新方案且已存在 `Published` 时：先二次确认；确认后在同一事务内把旧 `Published → Superseded`、新方案 `→ Published`；取消则不变。
  4. `Superseded` 方案只读、可查看/导出，不可再发布；不得删除（审计需要）。
  5. 学期存档时，当前 `Published → Archived`；学期变为只读。
  6. 新增 `SaveAsPlan`（另存）：复制课次与约束生成独立 `Draft`，名称、时间、冲突数独立；源方案不受影响。
  7. 发布前必须通过三类核心冲突校验（除已记录的人工豁免）。
- **影响**：TC-AP-005/006；M-02。
- **理由**：这是 D12 的直接落地；不补状态迁移，覆盖发布无法实现。

#### A-10 草稿状态下切换学期

- **疑问**：PRD §5 只写“未发布草稿切换学期时提示保存/放弃”；DDD 只有 `SwitchCurrentSemester` interaction，无命令、无守卫；TC-AP-007 要求“未明确选择则不执行切换，草稿不丢失”。
- **证据**：PRD §5/D12；DDD `applicationServices`；09 TC-AP-007。
- **裁决**：
  1. 新增 `SwitchCurrentSemester` 命令；切换前检查当前学期是否存在 `Draft` 方案。
  2. 若存在未发布草稿，弹出三选一：**保存 / 放弃 / 取消**。
     - **保存**：持久化当前草稿（含未保存编辑），然后切换；草稿保留在列表中。
     - **放弃**：丢弃自上次保存以来的未保存编辑；若草稿从未保存过则删除该草稿；需二次确认；确认后切换。
     - **取消**：不切换、不修改任何数据，草稿保持原状。
  3. 若不存在未发布草稿：直接切换，不弹框。
  4. 已保存草稿不会因切换而自动删除；只有显式“放弃”才会丢弃未保存内容。
- **影响**：TC-AP-007；M-19。
- **理由**：PRD 的“提示保存/放弃”需要明确第三选项“取消”，否则无法满足“未明确选择则不执行”。

### 4.5 排课能力

#### A-11 未排课时与冲突明细模型

- **疑问**：PRD F8/D14 要求“未排课时清单（可跳转定位）”，F17/D21 要求“冲突明细 + 修改建议”；DDD 只有校验服务，没有对应实体。
- **证据**：PRD F8/F17/D14/D21；DDD `ConflictValidationService`、`TimetablePlan`；09 TC-AP-003/004、TC-CE-001/002。
- **裁决**：
  1. 新增 `UnscheduledLesson`：`planId`、`assignmentId/combinedClassId`、`classIds[]`、`subjectId`、`teacherId`、`requiredPeriods`、`unplacedPeriods`、`reasonCode`、`reasonDetail`、`suggestedActions[]`、`sourceConfigRefs[]`。
  2. 新增 `ConflictDetail`：`planId`、`lessonId`、`conflictType`、`teacherId/classIds/venueId`、`weekday/period`、`ruleId`、`suggestion`、`resolutionState`。
  3. 每次生成/重新生成方案时重建两份清单，随方案持久化；查询接口可按方案读取。
  4. 清单项必须可定位：携带对象 id 与配置入口路由，前端可跳转。
  5. 未排课时不得伪造“0 冲突”；`conflictCount` 与未排课时数分别展示。
- **影响**：TC-AP-003/004、TC-CE-001/002；M-03/M-04。
- **理由**：没有持久化实体，D14/D21 的“清单/定位/建议”无法实现，也无法测试。

#### A-12 单双周与周次

- **疑问**：PRD D18 规定第 1 周单周、奇偶轮换、节假日停课不顺延；DDD 无 `weekParity`；节假日与“教学周序号”的定义未给出（05 建议 010）。
- **证据**：PRD F10/D18；DDD R-022；09 TC-AP-011/012/013。
- **裁决**：
  1. `LessonOccurrence` 增加 `weekParity`：`ALL / ODD / EVEN`；默认为 `ALL`。
  2. 奇偶由**教学周序号**决定，不由自然周决定；**第 1 教学周 = 单周（ODD）**。
  3. 停课周**继续占用周序号**，不使后续周次前移（D18“不顺延”）。
  4. 单周课表只展示 `ALL + ODD`，双周课表只展示 `ALL + EVEN`；同一课程可在两套结构中的不同节次出现。
  5. **教学周序号与自然日期/节假日的映射**已由 H-05 落定：周首为周一，学期开始日所在周为第 1 教学周，停课周占周序号且奇偶继续推进，部分停课周仍计 1 周，调休按配置的“周几课表”上课。
- **影响**：TC-AP-011/013；TC-AP-012 已随 H-05 恢复；M-05/M-10。
- **理由**：D18 已给出奇偶起点与不顺延；缺的只是日历映射，单独交 H-05，避免把技术默认值冒充产品决策。

#### A-13 走班基线

- **疑问**：PRD D9/F10 要求走班基线入 V1.0、动态深化留 V2.0；DDD 无走班组/多班参与模型，`LessonOccurrence.classId` 为单值。
- **证据**：PRD F10/D9；DDD `LessonOccurrence`、`CombinedClass`；09 TC-AP-014。
- **裁决**：
  1. V1.0 走班基线定义为：**按所选科目，将一组参与班级整体安排到指定场地，由指定教师授课**；不做学生个体选课/动态编排。
  2. 走班课是一个排课单元：占用 `teacherId + venueId + 时间段`，并占用全部参与班级的该时段。
  3. 冲突校验必须对“参与班级集合”逐班检查：任一参与班级在该时段已有课，即冲突；场地被占用即冲突；教师被占用即冲突。
  4. 与合班的区别：合班是静态合并的固定班级组；走班是按科目跨班流动的组，允许参与班级集合按科目配置。V1.0 两者共用“多班参与”的排课单元映射（M-06/M-21），但配置入口与语义分开。
  5. 动态走班编排（学生级、并行分组、分层）明确不在 V1.0；TC-AP-016 作为范围核对项，不作为系统测试。
- **影响**：TC-AP-014；M-06/M-21。
- **理由**：PRD 只要求“场地+教师双重分配”的基线；把它建模为多班参与的单排课单元，是最小可实现且可验证的解释。

#### A-14 跨年级授课

- **疑问**：PRD D9/F10 要求放开教师年级限制；DDD `TeachingAssignment` 可有多条记录，但未明确是否存在“同一年级”隐式约束。
- **证据**：PRD F10/D9；DDD R-024、`TeachingAssignment`；09 TC-AP-015。
- **裁决**：
  1. 系统**不设教师年级限制**；同一教师可在任意年级的班级任课。
  2. 冲突判定只看 `(teacherId, weekday, period)`、`(classId, weekday, period)`、`(venueId, weekday, period)`，与年级无关。
  3. 工作量统计按教师跨年级累计，不按年级拆分总额。
  4. 不存在“跨年级班级冲突”这一独立冲突类型；若出现，归入班级同节多课或教师时间冲突。
- **影响**：TC-AP-015。
- **理由**：PRD 明确“放开限制、不产生跨年级班级冲突”；年级不是排课维度。

#### A-15 撤销/重做与“成组批量”

- **疑问**：PRD F12 要求撤销/重做且“可成组批量”；DDD 只有 `UndoAdjustment`/`RedoAdjustment` interaction，无历史模型；未定义分组粒度、历史范围、跨用户边界。
- **证据**：PRD F12/D13；DDD `applicationServices`；09 TC-AT-007。
- **裁决**：
  1. **撤销单元 = 一次确认保存的调课事务**；一次保存若包含多个课程移动（批量/成组），整组作为一个撤销单元；重做同样整组重放。
  2. 历史按“方案 + 当前用户 + 当前编辑会话”维护，栈上限 50 个单元；超出后丢弃最旧单元，UI 在不可撤销/不可重做时禁用按钮。
  3. 离开方案或刷新页面后历史清空（V1.0 不持久化撤销栈）；已保存的课表数据不受影响。
  4. 撤销/重做必须重新执行冲突、锁定、容量校验；若当前状态已不允许该操作（如课程已锁定），整组拒绝并提示，不得部分应用。
  5. 撤销/重做本身不产生新的“调课保存”日志，但记录一条调整历史日志（模块=调课，动作=撤销/重做）。
  6. 该裁决同时关闭 O-AT-007-GROUP 的“成组批量”语义缺口；该子断言可在实现后恢复执行。
- **影响**：TC-AT-007；M-07。
- **理由**：把“成组”绑定到一次保存事务，是最小且可验证的定义，避免发明跨用户全局撤销。

### 4.6 统计与冲突处置

#### A-16 工作量统计口径

- **疑问**：PRD F14 写“连堂/合班/加班为加计类型，不与常规重复统计（连堂按节次、合班按 1 节）”；未说明一条课次同时属于合班与连堂时归入哪一类，也未说明四列之和是否等于总课时。
- **证据**：PRD F14/D7；DDD R-031；09 TC-AS-001/003。
- **裁决**：
  1. **每条课次只计入一个类别**，优先级：**合班 > 连堂 > 常规**。
  2. 合班按 **1 节**计，不按参与班级数乘计；连堂按 **实际节次**计（2 连堂=2）。
  3. 加班列 V1.0 恒为占位 0，不参与判定；显示“细则 V1.1”。
  4. 四列之和 = 总课时（加班为 0 时即前三列之和）；周口径与学期口径分别按对应范围内的课次重算。
  5. 统计必须从同一课表数据源计算，不得使用页面缓存或手工汇总。
- **影响**：TC-AS-001/003。
- **理由**：只有规定互斥优先级，才能同时满足“加计不重复”和“各列之和等于总课时”。

#### A-19 “只本次忽略”的边界与审计

- **疑问**：PRD F17/D21 允许对“由排课限制（约束/配置）引发的冲突”选择“只本次忽略”，并说明“豁免不落库为全局规则、不计为静默冲突”；但未说明：
  1. 三类核心冲突是否可忽略；
  2. “不落库”是否包括审计日志；
  3. 忽略的作用域（本次生成/本次调课/整学期）。
- **证据**：PRD F17/D21/V-5；DDD R-034、`IgnoreConflictOnce`；07 P19（“豁免不落库”）；09 TC-CE-004。
- **裁决**：
  1. **可忽略的前提**：冲突明细必须能归因到具体规则/配置（`ruleId`/`configRef`）；无归因的数据冲突不提供“只本次忽略”，只能“去修改配置”或取消。
  2. **不可忽略的硬项**：场地容量超限（D19 硬约束）、锁定课程被移动（F9）、已存档学期的写操作（D12）——这些没有“忽略”入口。
  3. 对可归因的冲突（包括三类核心冲突中由约束引发者），允许“只本次忽略”，但必须：
     - 二次确认，明确提示“本次将产生人工豁免，不计为静默冲突”；
     - 作用域仅为**本次生成/本次保存**，不写入任何全局配置；
     - 写入操作日志：操作人、时间、方案、冲突类型、涉及对象、规则 id、豁免范围；
     - 下一次排课/调课仍按原规则重新提示；
     - 方案上标记“含人工豁免”，导出/统计可识别。
  4. “豁免不落库”解释为**不落为全局规则/配置**，不排除审计日志；F19 的 100% 留痕优先。
- **影响**：TC-CE-004；M-17。
- **理由**：V-5 明确把“用户显式只本次忽略”定义为人工豁免，故不能一刀切禁止；但必须有归因、审计和范围限制，否则会退化为静默冲突。

### 4.7 权限、日志与视图

#### A-18 用户 CRUD 与服务端权限强制

- **疑问**：PRD F20 要求用户新增/编辑/停用/角色分配；DDD 只有 `ProvisionTeacherAccount` 与 `AssignRole`，无通用账号 CRUD；权限“即时生效”的时点未定义。
- **证据**：PRD F20/D11/§4；DDD `Account`、`IdentityService`；09 TC-AU-004/007/009。
- **裁决**：
  1. 新增命令：`CreateUser`、`UpdateUser`、`DisableUser`、`EnableUser`、`AssignRole`、`ResetPassword`（重置为随机密码并强制下次登录改密，见 H-02）。
  2. 角色仅 `Admin / Teacher`；账号 `username` 唯一；教师账号与 `teacherId` 一对一。
  3. **权限必须在服务端每个请求判定**；前端隐藏只作体验，不构成安全边界。越权请求返回 403 并提示无权限。
  4. 教师数据范围：本人课表、本人关联班级课表、本人空闲查询；不得访问全校/场地/其他教师视图与管理功能。
  5. 角色变更**在下一个请求即生效**：授权判定每次从当前账号数据读取角色，不在会话中缓存角色快照；已登录会话无需重新登录（会话有效性按 H-02：8h 空闲/7d 绝对，退出即失效）。
  6. 停用账号后，已存在会话在下一个请求被拒绝（H-02）。
- **影响**：TC-AU-004/007/009；M-09。
- **理由**：PRD 的“即时生效”可以通过“每请求读取当前角色”稳定实现，不必依赖会话刷新策略；这也满足 TC-AU-005 的会话内刷新路径。

#### A-20 日志“永久留存”的验收口径

- **疑问**：V-3/F19 要求“永久保存，不被清理”，但“永久”无法由有限测试证明；DDD `OperationLog` 无留存策略。
- **证据**：PRD V-3/F19；DDD `OperationLog`；09 TC-LG-001。
- **裁决**：
  1. “永久留存”在 V1.0 定义为**运行期无删除路径**：
     - 应用不提供删除/编辑日志的 API 或 UI；
     - 不存在自动清理任务/定时归档删除；
     - 应用重启、升级、数据库迁移后日志仍可查询；
     - 日志为追加写，不允许更新既有记录。
  2. 验收方式是“验证不存在删除能力 + 跨重启持久化 + 追加性”，**不宣称已证明无限期留存**。
  3. 备份/容灾策略不属于本验收，但部署文档必须说明日志随数据库备份。
  4. 若未来引入归档，必须保留可查询副本，且不得改变本口径。
- **影响**：TC-LG-001；O-LG-001-PERM；M-17。
- **理由**：把不可证明的“永久”转化为可执行的“无删除路径 + 持久化”，既满足产品意图，也能诚实验收。

#### A-21 五视图与“本人关联班级”

- **疑问**：PRD F11 要求教师仅可见“本人课表、本人关联班级课表”；“关联班级”未定义（任课班级？班主任班级？两者都算？）；DDD 无查询模型。
- **证据**：PRD F11/§4/D11；DDD R-025；09 TC-AT-003、TC-AU-009。
- **裁决**：
  1. “本人关联班级”= 该教师存在任一 `TeachingAssignment` 的班级 **或** 担任班主任的班级，二者并集。
  2. 教师可见：本人教师课表（全部任课）、上述关联班级的班级课表；可在关联班级间切换。
  3. 教师不可见：全校课表、场地课表、其他教师课表、任课视图中的非本人数据。
  4. 管理员可见全部五视图，并可选择任意对象。
  5. 五视图必须共享同一课表数据源，保证同一课次在不同视图中的科目/教师/班级/场地一致。
- **影响**：TC-AT-003、TC-AU-009；M-16。
- **理由**：把“关联”落到可查询的数据关系（任课 + 班主任），避免实现时各自解释。

## 9. 结论

1. **V1.0 的需求基线是可实现的**：20 项功能、89 条 TC、D15 基准均已闭合；47 条 TC 无需补模型即可执行。
2. **DDD 是“接近完整”的实现蓝图，不是完成品**：23 项最小补全是可落地的，且不改变 PRD 行为。
3. **原型只能看，不能跑**：其模拟逻辑与至少 18 处缺陷不得进入生产；07 报告的冒烟结论不可信。
4. **原先的 5 项不确定性已按用户授权落定**（2026-10-19）：并发采用乐观版本+刷新提示，认证采用最小安全基线，性能采用固定数据集+服务端 p95，数据交换采用 XLSX+固定模板+服务端 PDF，校历采用停课周占序号且奇偶推进。剩余工作是实现与验收；若部署环境、安全要求或校历规则变化，可重新裁决。
5. **不建议为通过测试而修改需求**：TC-BD-004 应退役/改写，TC-BD-008 由 A-08 补规则，TC-AP-016 降级为范围核对；其余孤儿在 H/A 裁决后恢复。
